# Phase 3.1 — Settlement-aware futures equity baseline

**Status:** Implemented  
**Date:** 2026-08-04  
**Predecessor:** Phase 3 account return (#15)

## Problem

MEXC `account/assets` returns many settlement wallets. The first row is often a
dust coin (e.g. STETH equity 0). Phase 2A stored only `data[0]`, so UI and
account-return history locked onto zero STETH and reported `opening_equity_zero`
even when USDT futures equity was available.

## Design

1. **Primary snapshot selection** (`select_primary_futures_raw`):
   - Prefer non-zero |equity|
   - Then preferred stables: USDT → USDC → USD → BUSD
   - Then higher |equity|
   - If all zero, still prefer USDT when present

2. **Latest snapshot for UI** (`latest_futures_account_snapshot`): same ranking
   within the newest `source_ts` batch.

3. **Account-return series**: choose one settlement asset series (same ranking by
   peak |equity| + preferred stables), then pick opening/ending endpoints
   (prefer first non-zero equity as open).

## Non-goals

- Multi-currency combined portfolio return
- Spot equity as futures collateral (still forbidden)
